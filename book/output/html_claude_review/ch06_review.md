### [1-3] `nunique()`와 `count()` 차이 설명 부족 — [섹션 5.10, 5.11]

**판단**  
타당합니다. `order_items`는 주문 1건이 여러 행으로 나뉠 수 있는 구조입니다. 따라서 주문 수를 계산할 때 `count()`를 사용하면 주문 상세 행 수가 계산되고, `nunique()`를 사용해야 고유 주문 건수를 계산할 수 있습니다. 이 차이는 결과 해석에 직접 영향을 줍니다.

**수정 방향**

- `order_count=("order_id", "nunique")` 코드 근처에 “고유 주문 건수”를 계산하기 위한 선택이라는 설명을 추가합니다.
- `count()`는 행 수를 세는 방식이므로 주문 상세 항목 수와 혼동될 수 있음을 안내합니다.

**판단**  
타당합니다. 카테고리별 매출을 계산할 때 `order_items`와 `products`만 병합하면 주문 상태를 고려하지 않습니다. 실무에서 “매출”이라고 표현할 경우 취소, 반품, 대기 주문을 포함할지 제외할지 기준이 필요합니다.

**수정 방향**

- 현재 예시는 “전체 주문 상세 기준 매출”인지 “완료 주문 기준 매출”인지 명시합니다.
- 실무에서는 보통 완료 주문 기준으로 매출을 집계한다는 주의 문장을 추가합니다.

## 5. 전반적 평가

Chapter 6은 EDA의 목적, 분석 질문 구성, 단변량/이변량 탐색, 질문 정리까지의 흐름이 비교적 잘 구성되어 있습니다. 다만 실무형 분석 교재로 사용하려면 **Notebook 파일명**, **주문 수 계산 기준**, **매출 집계 범위**는 반드시 정리해야 합니다.

반면 Claude가 지적한 경로 자동 감지 방식, CSV 인코딩, 0 나누기 방어, 연습 문제 채점 기준 등은 교재의 완성도를 높이는 보완점이지만, 현재 장을 학습할 수 없게 만드는 치명적 오류는 아닙니다. 따라서 후속 수정 작업에서는 필수 수정과 선택 보완을 분리해서 반영하는 것이 적절합니다.
