## 1. 필수 수정으로 유지할 항목

### [1-1] 수업 시간 합계와 본문 불일치 — [수업 시간 구성 표]

**판단**  
타당합니다. 표의 권장 시간 합계는 390분, 즉 6시간 30분입니다. 그런데 본문에는 “기본 수업은 약 4시간”이라고 되어 있어 차이가 큽니다. Chapter 8은 중간 프로젝트 장이므로 수업 시간 안내가 실제 운영과 맞아야 합니다.

**권장 수정 방향**

- 표를 4시간 내외로 줄이거나,
- 본문을 “기본 수업은 약 6시간 30분을 기준으로 구성되어 있습니다. 개인별 프로젝트 수행과 피드백까지 포함하면 1~2회차 수업으로 확장할 수 있습니다.”로 수정합니다.

### [1-2] 취소 주문 포함 매출 집계 기준 명확화 — [섹션 5.12, 5.13, 5.19]

**판단**  
타당합니다. 본문 해석 메모에서는 “취소 주문이 매출 계산에 포함되었는지 확인해야 합니다”라고 경고하지만, 실제 카테고리별·월별 매출 집계 코드에서는 주문 상태 기준을 명확히 선택하지 않습니다. 중간 프로젝트 제출물에서는 분석 기준이 중요하므로 이 항목은 필수 수정으로 유지하는 것이 좋습니다.

**권장 수정 방향**

- “완료 주문만 매출로 볼지, 전체 주문을 포함할지”를 명시합니다.
- 이번 실습에서 전체 주문을 포함한다면 보고서의 전처리/분석 기준에 반드시 기록하도록 안내합니다.
- 완료 주문 기준을 권장한다면 `completed` 상태의 주문만 분석 대상으로 삼는 별도 변수를 만들도록 안내합니다.

## 2. 보완 권장으로 낮출 항목

### [2-1] `to_csv()` 저장 인코딩 안내 — [섹션 5.2, 5.9, 5.12~5.14]

**재분류 사유**  
한글 데이터나 Windows Excel 사용 환경에서는 `utf-8-sig` 안내가 매우 유용합니다. 다만 `encoding` 옵션이 없다고 해서 pandas 코드가 실패하는 것은 아니므로 “필수 수정”보다는 “보완 권장”이 적절합니다.

**보완 방향**

- 본문에 “Windows Excel에서 CSV를 열 때 한글이 깨지면 `encoding="utf-8-sig"` 옵션을 사용한다”는 주의문을 추가합니다.
- 모든 코드에 일괄 적용하기보다 대표 저장 예시 1~2개에만 보여주어도 충분합니다.

---

### [2-2] `name` 컬럼 존재 미확인 — [섹션 5.14]

**재분류 사유**  
샘플 데이터 생성 스크립트의 `customers` 데이터에는 `name` 컬럼이 실제로 포함되어 있습니다. 따라서 현재 교재 흐름에서 바로 오류가 난다고 보기는 어렵습니다. 다만 외부 데이터를 사용하는 확장 실습에서는 컬럼명이 달라질 수 있으므로 방어적 설명은 유용합니다.

**보완 방향**

- “이 교재의 샘플 데이터에는 `name` 컬럼이 포함되어 있다”는 전제를 짧게 명시합니다.
- 외부 데이터를 사용하는 경우 `customers_clean.columns`로 컬럼명을 확인하라는 안내를 추가합니다.

---

### [2-3] 한글 폰트 하드코딩 — [섹션 5.1]

**재분류 사유**  
Windows 실습 환경에서는 `Malgun Gothic` 설정이 자연스럽습니다. Mac/Linux까지 모두 지원하는 자동 감지 코드는 좋지만, 중간 프로젝트 본문에 넣으면 초보자에게 코드가 길어질 수 있습니다.

**보완 방향**

- 본문에는 `Malgun Gothic`을 유지합니다.
- 주석 또는 팁으로 “Mac은 AppleGothic, Linux는 NanumGothic을 사용할 수 있다” 정도를 추가합니다.

---

### [2-4] `xticks(rotation=45)` 정렬 보완 — [섹션 5.16, 5.17]

**재분류 사유**  
`ha="right"`는 그래프 가독성 개선에는 좋지만, 코드 실행이나 개념 이해에 직접 오류를 만들지는 않습니다.

**보완 방향**

- 그래프 레이블이 겹치면 `plt.xticks(rotation=45, ha="right")`처럼 수정할 수 있다고 안내합니다.

---

### [2-5] 원본 데이터부터 다시 시작하는 이유 설명 — [도입부 또는 섹션 5.2]

**판단**  
타당한 보완입니다. Chapter 6~7에서는 전처리된 데이터를 활용했고, Chapter 8에서는 중간 프로젝트 특성상 원본 데이터부터 시작합니다. 이 차이를 설명하면 학습자가 반복처럼 느끼지 않고 “재현 가능한 분석” 관점으로 이해할 수 있습니다.

**보완 방향**

- “중간 프로젝트는 원본 데이터에서 보고서까지 한 번에 재현하는 것이 목표이므로, 앞 장에서 했던 전처리도 다시 포함한다”는 설명을 추가합니다.

## 5. 전반적 평가

Chapter 8은 Chapter 3~7의 내용을 하나의 중간 프로젝트로 묶는 장으로, 전체 흐름은 잘 구성되어 있습니다. 특히 원본 데이터 확인, 전처리, 키 관계 검증, 병합, 집계, 시각화, 보고서 작성까지 연결되는 구조가 좋습니다.

다만 실제 수업 운영과 제출물 평가를 고려하면 **수업 시간 안내**와 **매출 집계 기준**은 반드시 정리하는 것이 좋습니다. 반면 CSV 인코딩, OS별 폰트, 경로 자동 감지, 그래프 라벨 정렬, 컬럼 방어 코드는 실무적으로는 유용하지만 초보자용 중간 프로젝트 본문에서는 보완 또는 팁 수준으로 충분합니다.
