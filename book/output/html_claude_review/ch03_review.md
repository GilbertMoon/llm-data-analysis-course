## 2. 필수 수정에서 하향 조정할 항목

아래 항목은 반영하면 좋지만, 현재 원문이 틀렸다고 보기는 어렵습니다. 따라서 **필수 수정**이 아니라 **보완 권장** 또는 **낮은 우선순위**로 조정합니다.

### [1-1] 수업 시간 구성표 합계와 본문 불일치

**재검토 판단: 낮은 우선순위 보완**

원문은 기본 수업을 약 3시간으로 설명하고, 연습 문제와 심화 과제를 포함하면 최대 5시간으로 확장할 수 있다고 안내합니다. 표의 세부 시간 합계가 정확히 180분에 맞지는 않지만, 마지막 행이 `연습 문제 및 심화 과제 60~90분`으로 별도 확장 활동에 가깝기 때문에 치명적 오류는 아닙니다.

권장 수정은 다음 정도로 충분합니다.

```text
기본 수업은 약 3~4시간을 기준으로 구성되어 있습니다. 연습 문제와 심화 과제까지 포함하면 최대 5시간 분량으로 확장할 수 있습니다.
```

또는 표에 `기본 실습`, `확장 실습`을 구분해도 됩니다. 단, 이 항목을 최상위 필수 수정으로 둘 필요는 없습니다.

### [1-2] 데이터 경로 설정 코드에서 어떤 경로를 써야 하는지 불명확

**재검토 판단: 보완 권장**

원문은 프로젝트 루트에서 실행하면 `data/raw`, Notebook 폴더 안에서 실행하면 `../data/raw`를 사용한다고 이미 안내하고 있습니다. 따라서 내용 자체가 잘못된 것은 아닙니다.

Claude가 제안한 자동 감지 코드는 편리하지만, 초보자용 3장에서는 경로 개념을 직접 이해하는 것도 중요합니다. 자동 감지 코드로 완전히 교체하기보다는 다음과 같이 결론 문장을 추가하는 정도가 적절합니다.

```text
정리하면, Notebook을 프로젝트 루트에서 실행하면 `data/raw`, `notebooks` 폴더 안에서 실행하면 `../data/raw`를 사용합니다.
```

자동 감지 코드는 선택 보완 예시로 둘 수 있습니다.

### [1-5] `columns` 속성 출력 형태 미안내

**재검토 판단: 보완 권장**

`print(customers.columns)`와 `list(customers.columns)`의 차이를 보여주는 예시는 도움이 됩니다. 다만 현재 원문도 컬럼명 확인 목적과 LLM 코드 오류 가능성을 설명하고 있으므로 필수 수정까지는 아닙니다.

권장 수준:

```text
`customers.columns`는 pandas의 Index 형태로 보이고, `list(customers.columns)`는 일반 Python 리스트 형태로 보여줍니다. LLM에게 컬럼 목록을 전달할 때는 리스트 형태가 더 읽기 쉽습니다.
```

### [1-6] `signup_date` 날짜 변환 누락

**재검토 판단: 보완 권장, 필수 아님**

`signup_date`도 날짜형 컬럼이므로 함께 언급하면 좋습니다. 그러나 Chapter 3의 목표는 모든 날짜 컬럼을 완전히 전처리하는 것이 아니라, 데이터 구조와 타입을 확인하는 것입니다. 또한 본문 데이터 타입 표에는 이미 `order_date`, `signup_date`가 날짜형 분석 대상이라고 언급되어 있습니다.

따라서 `orders["order_date"]`만 예시로 다룬 것이 오류는 아닙니다. 권장 수정은 다음처럼 짧은 참고 문장을 추가하는 정도입니다.

```text
고객 데이터의 `signup_date`도 날짜형 분석에 사용할 수 있으므로, 같은 방식으로 `pd.to_datetime()` 변환 여부를 확인할 수 있습니다.
```

### [1-8] 쉼표 포함 문자열 변환 예시가 실제 데이터와 무관하게 등장

**재검토 판단: 낮은 우선순위 보완**

원문은 이미 “실무 데이터에서는 숫자가 `"10,000"`처럼 쉼표가 포함된 문자열로 저장되어 있는 경우도 있습니다”라고 설명합니다. 즉, 해당 예시가 실제 샘플 데이터가 아니라 실무 데이터 대비 예시라는 맥락은 어느 정도 제공되어 있습니다.

다만 학생 혼란을 줄이려면 다음 문장을 추가하면 충분합니다.

```text
현재 샘플 데이터에서는 이 변환이 필요하지 않을 수 있습니다. 아래 예시는 실무 데이터에서 가격이 문자열로 들어온 경우를 대비한 참고 예시입니다.
```

### [1-9] 키 관계 확인 실패 시 대처 방법 없음

**재검토 판단: 보완 권장**

원문에도 세 결과가 모두 0이면 연결 관계가 유지되고, 0보다 크면 어느 파일에서 기준 ID가 빠져 있는지 확인해야 한다고 안내되어 있습니다. 따라서 “대처 방법이 전혀 없다”는 평가는 다소 과합니다.

다만 실무적으로 다음 행동을 조금 더 구체화하면 좋습니다.

- 샘플 데이터라면 데이터 생성 상태를 다시 확인한다.
- 실무 데이터라면 누락 ID가 어느 파일에서 발생했는지 별도 표로 저장한다.
- 병합 시 `inner join`, `left join`, `outer join` 선택이 필요하다는 점은 이후 장에서 자세히 다룬다고 연결한다.

### [1-10] 결측치 처리 방법이 결과 해석 섹션에만 있고 실습 코드 섹션에는 없음

**재검토 판단: 반영 제외 또는 낮은 우선순위**

Chapter 3은 결측치를 “처리”하는 장이 아니라 “확인”하는 장입니다. 결측치 처리 코드를 3장에 많이 추가하면 Chapter 5 전처리 장과 역할이 겹칩니다.

현재 원문도 결측치 비율이 높다면 이후 전처리 단계에서 처리 방법을 결정해야 한다고 설명하고 있습니다. 따라서 3장에서는 다음 정도만 추가하면 충분합니다.

```text
이번 장에서는 결측치를 직접 처리하지 않고, 어느 컬럼에 얼마나 있는지 기록하는 것까지만 수행합니다. 실제 삭제·대체·보정은 5장 전처리에서 다룹니다.
```

## 3. 낮은 우선순위 또는 반영 제외 항목

아래 항목은 학습 흐름상 반드시 반영할 필요는 없습니다.

### [2-3] `pd.to_numeric()` vs `astype(float)` 차이 설명

**판단: 참고 수준**

비교 설명은 유용하지만, 3장에서 반드시 다룰 필요는 없습니다. 초보자에게 여러 대체 방법을 동시에 제시하면 오히려 혼란스러울 수 있습니다. 현재처럼 `pd.to_numeric(errors="coerce")` 한 가지 안전한 패턴을 먼저 익히게 하는 것이 더 적절합니다.

### [2-5] `isna()` vs `isnull()` 둘 다 사용 가능함을 언급

**판단: 반영 제외 가능**

두 함수가 동일하다는 정보는 참고로는 좋지만, 초보자 교재에서는 한 가지 표현을 일관되게 사용하는 것이 더 중요합니다. 본 교재에서는 `isna()`로 통일하는 것이 좋습니다.

### [2-6] `errors="coerce"`의 모든 옵션 설명

**판단: 낮은 우선순위**

`errors="raise"`, `errors="ignore"`까지 모두 설명하면 옵션 설명이 길어져 핵심 흐름이 흐려질 수 있습니다. 3장에서는 “변환 실패 값을 NaN 또는 NaT로 바꾸고, 변환 실패 건수를 확인한다” 정도면 충분합니다.

### [2-7] 섹션 간 전환 문장 부재

**판단: 선택 보완**

전환 문장이 있으면 읽기 좋지만, 필수 수정은 아닙니다. HTML/PDF 교재 가독성을 높이는 편집 단계에서 반영하면 됩니다.

### [2-8] 연습 문제에 힌트/채점 기준 없음

**판단: 선택 보완**

과제 운영 방식에 따라 힌트가 필요할 수 있습니다. 다만 모든 연습 문제에 힌트를 넣으면 평가 난이도가 낮아질 수 있으므로, 강사용 자료나 별도 힌트 파일로 분리하는 것도 가능합니다.

### [2-10] `describe(include="all")` 미안내

**판단: 참고 수준**

`describe(include="all")`은 유용하지만, 3장의 기본 흐름에서는 숫자형 통계와 범주형 빈도 확인을 분리해 가르치는 현재 구조가 더 명확합니다. 문자형 컬럼은 이미 `value_counts()`와 `nunique()`로 다루고 있으므로 필수 보완은 아닙니다.

## 6. 전반적 평가

Chapter 3 원문은 데이터 구조 파악의 목적, CSV 파일 4개 로드, 행·열·컬럼·타입·결측치·중복·키 관계 확인 흐름이 잘 잡혀 있습니다. 특히 원본 데이터를 LLM에 그대로 넣지 않고 구조 요약만 전달해야 한다는 보안 원칙을 포함한 점은 적절합니다.

다만 초보자 관점에서는 몇몇 pandas 문법이 갑자기 등장합니다. 우선적으로는 `isin()`과 `~` 연산, `def` 함수, `datasets` 딕셔너리 반복문, `describe()` 결과 해석을 보강하는 것이 가장 효과적입니다.

반대로 결측치 처리 코드, `describe(include="all")`, `astype(float)` 비교, `isnull()` 동의어 설명처럼 이후 장 또는 참고 수준의 내용은 3장 본문에 모두 넣기보다 필요한 경우 보충 설명으로 분리하는 편이 좋습니다.
