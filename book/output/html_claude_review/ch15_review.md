### [1-2] `to_markdown()` 사용 시 `tabulate` 의존성 안내 부족

**현재 상태**

ch15는 LLM 활용 기록과 최종 보고서 생성 과정에서 `DataFrame.to_markdown(index=False)`를 여러 번 사용합니다.

**문제**

`pandas.DataFrame.to_markdown()`은 내부적으로 `tabulate` 패키지를 필요로 합니다. 그런데 현재 저장소의 `requirements.txt`에는 `tabulate`가 포함되어 있지 않습니다. 학생이 깨끗한 환경에서 실행하면 보고서 생성 단계에서 `ImportError`가 발생할 가능성이 있습니다.

**판단**

이 항목은 필수 수정으로 유지합니다. ch15의 최종 산출물인 Markdown 보고서와 LLM 활용 기록 생성에 직접 영향을 주기 때문입니다.

**수정 권장 방향**

아래 중 하나를 반영합니다.

| 방식 | 수정 방향 |
| --- | --- |
| 권장 | `requirements.txt`에 `tabulate` 추가 |
| 보완 | ch15 도입부 또는 5.2 기본 패키지 안내에 `tabulate` 설치 필요 문구 추가 |
| 대안 | `to_markdown()` 대신 `to_string(index=False)` 또는 직접 표 문자열 생성 방식 사용 |

## 6. 전반적 평가

ch15는 전체 교재를 마무리하는 기말 종합 프로젝트 장으로, 데이터 불러오기, 전처리, pandas 분석, 시각화, LLM 활용, 보고서 작성, 자동화 설계를 하나의 흐름으로 잘 통합하고 있습니다. 제출 산출물 목록과 평가 기준이 명확하고, LLM 활용 기록과 자동화 설계까지 포함한 점도 실무형 강의에 적합합니다.

다만 최종 프로젝트 장이므로 실행 재현성과 제출 안정성이 특히 중요합니다. 가장 먼저 정리할 부분은 `to_markdown()` 실행 의존성입니다. 그다음으로 수업 시간 기준을 실제 운영 시간과 맞추고, 매출 분석 기준과 제출 전 실행 검증 체크리스트를 보완하면 기말 프로젝트 장의 완성도가 높아집니다.
