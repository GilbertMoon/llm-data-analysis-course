14장. 반복되는 분석 흐름을 자동화하기

이 장에서는 온라인 쇼핑몰 분석 흐름을 입력 확인 → 전처리 → 분석 → 시각화 → 보고서 생성 → 산출물 검증 단계로 나누고, Python 스크립트와 Docker Compose 기반 Airflow DAG로 실행 순서를 관리합니다.

1. Docker 설치는 별도 가이드 참고

Docker 설치 과정은 이 강의안에 길게 포함하지 않습니다. Docker Desktop 설치와 기본 확인은 아래 블로그 글을 참고합니다.

  • Docker 설치 가이드: https://blog.naver.com/dev-dog/224341211248

설치 후 아래 명령이 정상 동작해야 합니다.

docker --version
docker compose version
docker run hello-world

2. 자동화 흐름

단계하는 일입력출력
입력 확인원본 데이터 확인data/raw/*.csv확인 결과
전처리결측치, 타입, 중복 처리원본 CSVdata/processed/*_clean.csv
분석주요 지표 계산전처리 데이터reports/*.csv
시각화그래프 생성분석 결과 CSVreports/figures/*.png
보고서Markdown 보고서 작성표, 그래프reports/*.md
검증결과 파일 존재 여부 확인산출물 목록검증 로그

3. 이번 장의 DAG 구조

check_input_files
→ run_preprocessing

4. 실습 파일 구조

automation/airflow/
├─ Dockerfile
├─ docker-compose.yml
├─ requirements.txt
├─ .env.example
└─ dags/
   └─ ch14_local_analysis_pipeline.py

Airflow 컨테이너 내부에서는 프로젝트 루트를 /opt/airflow/project로 사용합니다.

5. Python 파이프라인 사전 검증

Airflow 실행 전에 Python 분석 코드 자체가 정상인지 먼저 확인합니다.

python scripts/generate_sample_data.py
python scripts/run_ch14_pipeline.py

6. Docker Compose로 Airflow 실행

automation/airflow 폴더에서 실행합니다.

cd automation/airflow

환경변수 예시 파일을 복사합니다.

# macOS / Linux / WSL2
cp .env.example .env

# Windows PowerShell
copy .env.example .env

최초 1회 초기화합니다.

docker compose up airflow-init

Airflow를 실행합니다.

docker compose up

7. Airflow UI 접속

http://localhost:8080
ID: airflow
PW: airflow

UI에서 ch14_local_analysis_pipeline DAG를 찾고 수동 실행합니다.

8. 산출물 검증

reports/ch14_daily_sales.csv
reports/ch14_category_sales.csv
reports/figures/ch14_daily_sales.png
reports/ch14_airflow_report.md
reports/ch14_airflow_validation_log.csv

검증 로그의 모든 status가 ok이면 주요 산출물이 정상 생성된 것입니다.

9. 종료와 초기화

docker compose down

docker compose down --volumes --remove-orphans

볼륨까지 삭제하면 Airflow 메타데이터 DB와 DAG 실행 기록이 초기화됩니다.

10. 정리

  • Docker 설치는 별도 블로그 글로 분리합니다.

  • Airflow 실행 전 Python 파이프라인을 먼저 검증합니다.
  • Airflow UI에서 DAG 실행 순서, 실패 로그, 산출물 검증을 확인합니다.
