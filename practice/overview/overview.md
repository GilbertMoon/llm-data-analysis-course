# STEP 7. LLM 사용 원칙 확인하기

## 7-1. 목적

이 강좌에서 LLM은 정답 생성기가 아니라 **분석 보조 도구**입니다.

## 7-2. 실행

다음 흐름을 기억합니다.

```text
사람이 질문 정의
→ LLM이 초안 지원
→ 실제 데이터와 코드로 검증
→ 사람이 수정
→ 사람이 최종 판단
```

LLM은 다음 작업을 도울 수 있습니다.

- 분석 질문 구체화
- pandas 코드 초안
- 오류 메시지 설명
- 시각화 코드 구조 제안
- 모델 코드 검토
- 보고서 표현 보완

하지만 다음 문제를 만들 수도 있습니다.

- 존재하지 않는 컬럼 사용
- 잘못된 병합 관계
- 데이터 누수
- 데이터에 없는 원인 단정
- 잘못된 API 사용법
- 위험한 파일·네트워크 코드

## 7-3. 예상 결과

다음 두 문장을 구분할 수 있어야 합니다.

```text
LLM이 자연스럽게 설명했다.
```

```text
실제 데이터와 코드로 검증했다.
```

두 문장은 같은 의미가 아닙니다.

## 성공 기준

- [ ] LLM 결과를 그대로 정답으로 사용하지 않습니다.
- [ ] 실제 컬럼·수치·범위·평가 방법을 다시 확인합니다.
- [ ] 최종 판단은 사람이 한다는 것을 이해했습니다.

## 오류가 나면

LLM의 답변이 확신에 차 있어 보여도 실제 데이터와 맞는지 확인합니다. 코드가 실행된다는 사실만으로 분석이 올바르다고 판단하지 않습니다.

# STEP 8. 개인정보와 Secret 보호 원칙 확인하기

## 8-1. 목적

Public 저장소와 LLM을 사용할 때 공개하면 안 되는 정보를 구분합니다.

## 8-2. 실행

다음 항목을 Public GitHub, 블로그, Notebook 출력 또는 LLM 입력에 그대로 넣지 않습니다.

```text
실제 이름
이메일
전화번호
주소
민감한 고객 식별값
내부 주문 식별값
DB 비밀번호
API Key
Client Secret
Access Token
내부 URL
내부 파일 경로
```

API Key가 필요한 장에서는 코드에 직접 값을 쓰지 않고 `.env` 또는 승인된 Secret 관리 방법을 사용합니다.

잘못된 예:

```python
API_KEY = "실제_API_KEY"
```

## 8-3. 예상 결과

실습 저장소에는 실제 Secret이 없어야 합니다.

`.env.example`에는 예시 변수명과 placeholder만 있을 수 있으며, 실제 `.env`는 Git에 올리지 않습니다.

## 성공 기준

- [ ] 실제 개인정보를 Public 저장소에 넣지 않습니다.
- [ ] 실제 API Key와 Secret을 코드에 직접 작성하지 않습니다.
- [ ] 화면 캡처와 오류 로그에도 민감정보가 없는지 확인합니다.
- [ ] 외부 데이터는 출처와 이용조건을 확인한 뒤 사용한다는 것을 이해했습니다.

## 오류가 나면

실제 Secret이 이미 공개된 경우 단순히 코드에서 문자열만 지우는 것으로 끝내지 않습니다. 해당 Key를 폐기·재발급하고 Git 기록과 로그 노출 여부를 확인해야 할 수 있습니다.

# STEP 9. 각 Chapter의 실습 방법 이해하기

## 9-1. 목적

앞으로 모든 실습에서 같은 방식으로 결과를 확인하는 습관을 만듭니다.

```text
정상이라면 무엇이 나와야 하는가?
결과가 맞는지 어떻게 검증하는가?
오류가 나면 첫 원인은 무엇인가?
```

단순히 Notebook의 모든 셀이 초록색으로 끝나는 것을 목표로 하지 않습니다.

```text
코드 실행 성공
≠
분석 검증 성공
```

각 Chapter에서 숫자·행 수·총합·그래프·데이터 누수·보안·해석 등 해당 장의 성공 기준을 별도로 확인합니다.

## 성공 기준

- [ ] 각 실습 STEP의 목적을 먼저 읽습니다.
- [ ] 예상 결과와 실제 결과를 비교합니다.
- [ ] 성공 기준을 체크합니다.
- [ ] 오류가 발생하면 첫 오류부터 확인합니다.
- [ ] 결과 Evidence를 남깁니다.

## 오류가 나면

오류가 여러 개 보일 때 마지막 오류부터 무작정 수정하지 않습니다. **처음 발생한 원인**과 그 직전 단계의 입력을 먼저 확인합니다.
