# 제출 가이드

## LMS 제출 방식

LMS 과제 게시판에 제출 파일 또는 GitHub URL을 업로드합니다. 제출 전 노트북이 위에서 아래로 정상 실행되는지 확인합니다.

## GitHub 제출 방식

본인 GitHub 저장소에 실습 결과를 push한 뒤 저장소 URL 또는 Pull Request URL을 제출합니다. 제출용 저장소에는 실행 결과가 포함된 노트북, 보고서, 프롬프트 로그를 함께 정리합니다.

## 주차별 실습 제출 파일

주차별 실습은 수업 운영 방식에 따라 전체 제출 또는 일부 주차 제출로 조정할 수 있습니다.

기본 제출 파일은 다음과 같습니다.

- 주차별 Jupyter Notebook
- 분석 결과 그래프 이미지
- 간단한 해석 메모 또는 Markdown 정리
- LLM을 사용한 경우 프롬프트 로그

## 중간 프로젝트 제출 안내

중간 프로젝트는 8주차에 진행합니다. 샘플 쇼핑몰 데이터를 활용해 EDA와 시각화 중심의 분석 결과를 제출합니다.

권장 제출 파일은 다음과 같습니다.

- 중간 프로젝트 Jupyter Notebook
- 분석 질문 3개 이상
- 전처리 과정
- 주요 집계 결과
- 시각화 그래프 2개 이상
- 데이터에 근거한 인사이트 요약
- LLM 사용 시 프롬프트 로그

머신러닝은 중간 프로젝트의 필수 항목이 아니라 선택 확장 항목으로 둘 수 있습니다.

## 기말 프로젝트 제출 안내

기말 프로젝트는 15주차에 진행합니다. 중간 프로젝트보다 확장된 형태로, EDA, 시각화, 머신러닝, LLM 활용, 보고서 작성, 자동화 아이디어를 함께 정리합니다.

권장 제출 파일은 다음과 같습니다.

- 최종 분석 Jupyter Notebook
- 회귀 또는 분류 모델 중 1개 이상
- 모델 평가 결과와 해석
- 분석 결과 그래프 이미지
- Word 또는 PDF 보고서
- 프롬프트 로그 문서
- 자동화 아이디어 또는 간단한 파이프라인 설계안
- 프로젝트 발표 자료가 있는 경우 별도 첨부

## 프롬프트 로그 제출 안내

LLM을 사용한 경우 어떤 질문을 입력했고, 어떤 답변을 분석에 반영했는지 기록합니다. 프롬프트 로그는 결과의 신뢰성과 재현성을 확인하기 위한 자료입니다.

프롬프트 로그에는 다음 항목을 포함하는 것을 권장합니다.

| 항목 | 내용 |
| --- | --- |
| 사용 목적 | 분석 질문 생성, 코드 작성, 오류 해결, 결과 해석, 보고서 작성 등 |
| 입력 프롬프트 | LLM에게 입력한 핵심 질문 |
| 답변 요약 | LLM 답변 중 실제 참고한 내용 |
| 반영 여부 | 실제 분석에 반영했는지 여부 |
| 검증 내용 | 코드 실행, 컬럼 확인, 결과 비교 등 본인이 검증한 내용 |

## LLM 사용 시 주의사항

- API Key와 개인정보를 입력하지 않습니다.
- LLM이 생성한 코드는 직접 실행하고 결과를 검증합니다.
- 데이터에 근거하지 않은 과장된 해석을 보고서에 쓰지 않습니다.
- LLM 답변을 그대로 복사하지 말고 본인의 분석 맥락에 맞게 수정합니다.
- 모델 평가 결과는 정확도 하나만 보지 말고 문제 성격에 맞는 지표를 함께 확인합니다.
